容器里的 systemctl 仅将 Nginx 重载映射为真实 nginx -s reload；上述访问结果不能作为 systemd 服务管理的验收。初次 WebSocket 验证观察到平滑重载存在短暂生效延迟。后续已增加本机配置标识确认，重载信号返回 0 不再被当成配置已经生效；确认失败恢复原配置。该修复已通过真实端口占用及释放后重试回归。

## 本地 ACME 追加验收（2026-11-20）

复用 Debian 12 amd64 独立测试机的磁盘快照，使用真实 Certbot 2.1.0、Nginx 和 systemd，通过 Pebble 测试 CA 校验 HTTP-01。测试 CA 从 Nginx 的 80 端口实际读取验证文件。 [Pebble](https://github.com/letsencrypt/pebble)

| 路径 | 实际结果 |
| --- | --- |

| 修复并重试 | 加入测试域名解析后签发成功。Nginx 对 ACME 验证文件返回 200，客户端验证证书链和域名后可通过 HTTPS 访问面板。 |
| 续期与生效 | 启动 `lpanel-renew.service` 后，Certbot 更新证书。Nginx 实际提供的证书序列号与新文件一致。 |
| 续期失败 | 停止测试 CA 后，续期服务失败。现有证书序列号保持原值，HTTPS 仍可访问。 |

## 本机防火墙（2026-11-22）

在 Ubuntu Base 24.04.5 amd64、UFW 0.36.2-6 上运行面板与真实 Nginx。服务端、客户端分别在独立网络命名空间，通过虚拟网线通信。每个场景使用独立的文件系统副本，未切换开发宿主机的防火墙。

| 隔离环境 | 新连接实测 |
| --- | --- |
| 默认拒绝入站，无面板放行项 | 通过面板启用后，客户端仍能打开 `18443` 的原面板地址；新 SSH 密钥登录失败。在面板放行 `2222/TCP` 后能登录，删除 IPv4 规则后再次被拦截；停用后恢复。原有 `25000/UDP` 规则保留。 |
| 面板限来源 | 通过允许的 IPv4、IPv6 来源分别启用，启用前后规则标识和顺序一致；IPv4 测试的第二个来源仍连不上。 |
| 先拒绝面板端口，再允许指定来源 | 启用返回冲突，UFW 仍停用。 |
| 原已允许 SSH | 启用防火墙并新增无关 UDP 拒绝规则后，新 SSH 密钥登录仍成功。 |
| 默认转发为 `DROP`，已有非 UFW 转发链 | 启停后从系统核对，原有跳转、链中规则和默认 `DROP` 均保留。此场景模拟转发配置，不代表完整 Docker 数据面实测。 |

SSH 验证使用 OpenSSH 客户端和仅响应测试命令的 SSH 服务，不替代目标机 sshd 配置验收。Chrome 通过实际 Nginx、面板和 UFW 核对启用、刷新、添加端口、手机宽度和停用；模拟接口另覆盖读写失败与错误文案。未实测 Debian 系统启动、真实云安全组和 Docker 转发流量。
