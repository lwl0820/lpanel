# 首版验证记录

本记录覆盖本地构建的 v0.1.0 和正式发布的 v0.1.1，包含自动化测试、分环境实测结果和待人工验收项。

## 自动化检查

- Go 项目测试及 go vet 通过，覆盖登录会话、配置、持久化操作、域名/证书结果、Compose、网站回退和升级。
- 前端类型检查、ESLint、4 项 API 测试及生产构建通过。网络中断和 Nginx HTML 错误页均有中文错误回归测试。
- 安装、发行脚本 Bash 语法检查通过。
- 完整导入 Element Plus 的生产包有体积提示，按已批准方案保留直接导入，未为此增加构建插件或更改产品范围。

## 真实 Docker 与 Nginx 联调

在一次性测试容器中执行，未安装或改写宿主机 Nginx。

| 路径 | 实际结果 |
| --- | --- |
| Compose 配置规范化 | CLI 真实解析短/长端口、变量、expose 与包含版本警告的输出 |
| 项目生命周期 | 真实创建容器，动态发布端口 HTTP 200，停止/启动可用，删除后命名数据卷仍保留 |
| Nginx 面板入口 | 使用程序生成配置，前端页面 HTTP 200，健康 API 返回 v0.1.0，真实管理员登录与 Cookie 会话通过 |
| 静态网站 | 通过实际 API 创建目录网站和绑定，域名访问首页与 SPA 子路由返回一致内容 |
| ACME 公开文件路径 | 验证 token 直接返回预期内容，未被 SPA 回退吞掉 |
| 应用代理 | 绑定上游 HTTP 服务后，经 Nginx 返回真实健康 API |
| WebSocket | 产品 API 创建代理，握手返回 101，校验 Sec-WebSocket-Accept，发送掩码文本帧并收到正确双向回显 |
| Nginx 重载失败回退 | 真实占用 443，证实重载命令返回 0 但配置未生效；修复后操作失败、旧 HTTP 保留，释放端口后重试成功 |
| HTTPS 配置生效 | 使用本地测试签发替身，Nginx 实际提供 TLS；客户端仅信任本次测试证书并验证域名，HTTPS 静态访问通过，不代表公网 CA 签发 |

容器里的 systemctl 仅将 Nginx 重载映射为真实 nginx -s reload；上述访问结果不能作为 systemd 服务管理的验收。初次 WebSocket 验证观察到平滑重载存在短暂生效延迟。后续已增加本机配置标识确认，重载信号返回 0 不再被当成配置已经生效；确认失败恢复原配置。该修复已通过真实端口占用及释放后重试回归。

## 安装脚本分支

tests/install-smoke.sh 在隔离 Debian 容器中执行真实脚本与文件安装，包管理、系统服务、面板程序和证书结果使用命令替身。已验证首次安装、密码不进入程序参数、重复安装不覆盖账号、外部 Nginx/端口冲突拒绝、证书失败回到服务器 IP 的 HTTP 地址。

## 发行包

scripts/build-release.sh 已构建 amd64、arm64 两种 Linux 包，包内包含程序、前端、主服务、续期服务与安装脚本。归档内容和 SHA-256 文件已检查，amd64 程序已在 Alpine Nginx 容器中实际运行。构建产物位于工作目录 .tmp/releases。

## 首轮目标环境待验收

首轮测试时以下条件尚未具备，后续验证见下方追加记录。

1. 公网普通域名的 Let’s Encrypt 测试及正式签发、续期和 HTTPS/WSS 访问。
2. Debian/Ubuntu 目标矩阵的真实 apt 安装、systemd 主服务/续期 timer、服务器重启和升级进程切换/失败恢复。
3. arm64 实机运行；目前只有交叉编译产物。
4. 真实 GitHub 仓库正式发布和从该仓库在线安装/升级；目前使用本地包及 HTTP fixture 验证契约。

首轮验收范围不包含应用商店、泛域名、DNS 服务商接入、多机管理、文件上传等能力。目标服务器首次部署时按安装说明提供真实发行源、域名与网络条件即可进入外部验收。

## 本地 ACME 追加验收（2026-11-20）

复用 Debian 12 amd64 独立测试机的磁盘快照，使用真实 Certbot 2.1.0、Nginx 和 systemd，通过 Pebble 测试 CA 校验 HTTP-01。测试 CA 从 Nginx 的 80 端口实际读取验证文件。 [Pebble](https://github.com/letsencrypt/pebble)

| 路径 | 实际结果 |
| --- | --- |
| 签发失败 | 测试 DNS 缺少域名地址时，Certbot 报告验证失败，面板的 HTTP 健康接口仍可访问。 |
| 修复并重试 | 加入测试域名解析后签发成功。Nginx 对 ACME 验证文件返回 200，客户端验证证书链和域名后可通过 HTTPS 访问面板。 |
| 续期与生效 | 启动 `lpanel-renew.service` 后，Certbot 更新证书。Nginx 实际提供的证书序列号与新文件一致。 |
| 续期失败 | 停止测试 CA 后，续期服务失败。现有证书序列号保持原值，HTTPS 仍可访问。 |
| 自定义面板端口 | 改用 19443 后，从业务端口 80 跳转到带端口的 HTTPS 地址，健康接口返回 v0.1.1。 |
