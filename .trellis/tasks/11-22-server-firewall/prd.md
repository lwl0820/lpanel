# 防火墙管理

## 已确认：启停与面板端口保护

管理员可以查看、启用和停用本机防火墙。每次启用前，按以下顺序保护当前面板入口：

1. 自动读取当前生效的面板对外端口（面板配置的 `panel_port`）。不假定端口为默认值 `8443`，也不把后端回环监听端口当成对外入口。
2. 检查启用后将生效的 TCP 入站规则。已有允许当前管理连接来源访问该端口的规则就沿用；缺少放行规则时先自动补上。不能仅因列表里有一条允许规则就忽略优先匹配的拒绝规则。
3. 确认面板端口允许入站后才启用。无法识别端口、写入规则失败或无法确认放行时，保持未启用，并告知管理员原因。已有来源限制不因本次启用自动扩大。

启用保护只针对面板入口。启用时不检测、不提示、不自动放行 SSH，也不改动已有 SSH 规则。SSH 被拦截不影响启用；管理员仍可登录面板，手动为实际 SSH 端口设置入站规则。

## 端口规则范围

管理员能维护单个入站端口的允许或拒绝规则，区分 TCP 和 UDP。首版不接管云安全组、Docker 的转发规则，也不做自定义规则脚本。

## 验收标准

- [x] 对照隔离服务器的实际状态，未启用不会显示为启用；不把一条本机允许规则描述为「公网已放通」。
- [x] 在隔离服务器将面板改为非默认端口，且预先不放行该端口。从另一台机器通过面板启用防火墙后，用新连接仍能打开原面板地址；规则只新增所需的面板放行项，不误开放默认端口或后端回环端口。
- [x] 在默认拒绝入站且没有 SSH 放行规则的隔离服务器上启用防火墙，全程无 SSH 提醒。确认新的 SSH 连接被拦截后，通过新连接登录面板，手动放行实际 SSH 端口；SSH 随后可重新连接。
- [x] 已有适用的放行规则时不重复添加，不拓宽其来源范围。若端口无法识别、规则添加失败，或已有冲突规则导致无法确认入站，防火墙保持未启用，页面说明原因。
- [x] 从面板停用防火墙后重新打开页面，页面和隔离服务器均显示未启用。
- [x] 在已有基础规则的测试机上，为测试服务添加端口规则，从另一台机器核对连接结果；删除新增规则后恢复原有行为，其他规则保持不变。
- [x] 测试机若原已放行 SSH，修改无关端口规则后，原有 SSH 访问不受影响。不在开发宿主机上切换防火墙。

实际测试环境、命令替身和未覆盖范围见 `docs/validation.md` 的「本机防火墙」。
