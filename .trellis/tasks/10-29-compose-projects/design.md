# Docker Compose 项目部署技术设计

以[总任务设计](../10-29-server-management-panel/design.md)为跨模块契约，本文件明确子任务负责范围。

## 配置与解析
项目目录持久化原始 compose.yaml 和 .env。调用 docker compose config --format json 验证并规范化，不自己实现 YAML、变量替换或端口短格式解析。扫描返回服务、来源、协议、容器端口和发布地址；前端类型对应同一响应结构。

## 部署与代理
用参数数组指定项目路径及项目标识，调用 Compose v2 生命周期命令。部署完成后读取实际发布映射，特别是动态宿主端口；管理员指定上游 HTTP/HTTPS，不根据端口号推断服务类型。通配宿主地址使用回环访问，指定绑定地址使用实际地址。expose-only 不直接生成不可达上游。

绑定关系引用稳定的项目、服务和容器端口，重新部署后刷新实际宿主端口。项目状态和日志从 Docker 获取；部署等长操作使用基础框架操作记录，不用页面请求阻塞整个过程。

## 删除与验证
先移除项目域名代理，再执行 compose down；不传 --volumes，不删除挂载路径。扫描逻辑测试覆盖常见格式，集成测试验证真实部署、WebSocket、端口变动和保留卷。
