以下是待创建代码应提供的验证入口，当前不执行，也不把不存在的脚本报告为通过。

```bash
go test ./...

npm --prefix web run build
bash -n deploy/install.sh
```

Go 测试设置 TMPDIR 到工作目录 .tmp，并使用 t.Setenv 等方式确保测试文件不写系统临时目录；SQLite 测试同样使用 .tmp 内的独立目录。仅为高风险路径和接口契约编写有意义的测试，不测试文案与实现自身的重复细节。

## 必须覆盖的行为
- 登录错误、未登录调用、密码不进入日志；持久化重启后管理员可继续登录。
- Compose ports 的短/长格式、变量、多个服务端口、expose-only、UDP、动态宿主端口及删除保留卷。
- 不同资源共用域名/证书流程；自定义面板端口不影响公网 80 验证路径。
- Nginx 配置无效时恢复旧文件；静态 SPA 回退不吞掉 ACME 验证路径。
- ACME 测试环境签发、错误域名失败、修复后重试、续期后证书生效。
- 更新版本比较、无更新、下载失败、缺少架构附件、新进程失败后回退；升级过程中后端退出不终止升级进程。
- 安装环境/端口冲突不覆盖现有配置；重跑不覆盖管理员或数据；系统重启后入口可用。

## 环境验证与边界
在隔离虚拟机或专用测试服务器验证 systemd、Docker、Nginx；普通容器测试不能替代 systemd/内核行为验收。Debian/Ubuntu 与两种架构按设计矩阵记录实际结果，缺少机器必须标为未验证。首次真实公网验证使用测试 ACME 服务，正式证书留作发布前验收。

## 改动风险与恢复点
- Nginx 配置：每次只改面板拥有的文件，保存旧文件，检查失败恢复。
- 发行切换：旧版本目录与 current 指针必须保留；失败恢复上一版。
- 数据：不删除项目卷、网站目录或证书；不在首版自动升级中引入破坏性迁移。
- 安装：先检查再改系统；首次安装中断时保留明确结果，不自动卸载原有软件。
