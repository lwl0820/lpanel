# 技术设计

## 已有边界

internal/panel/projects.go 的 ProjectStatus 从当前项目的 Compose ps 获取容器、运行状态和 Publishers。projectUpstream 已能按服务和容器端口解析最新上游。配置扫描还承担保存项目前的 Compose 校验。web/src/components/BindDomainDialog.vue 在两个入口共用，分别加载项目详情和端口选项。

## 从运行容器到候选端口

给已登记项目新增只读运行端口查询。由服务端按项目 ID 获取运行容器。已发布候选复用原有上游解析规则，展示的宿主机端点要与实际提交后选中的一致。多个副本映射到不同宿主机端口时，沿用已有的按服务绑定行为。

对 host 容器，读取 Docker 网络模式及该容器的进程集合，在宿主机将容器进程持有的监听套接字与 Linux TCP 监听表关联。共享网络命名空间内的监听表本身无法证明进程归属。覆盖容器子进程和精简镜像，避免依赖镜像内安装诊断工具。使用实际本地监听地址生成宿主机 Nginx 可用的目标，IPv4/IPv6 通配监听分别使用对应族的回环地址，具体监听地址沿用其本地地址。

## 从候选到域名

查询返回服务、来源和端口信息。弹窗用独立分组呈现已发布映射、host 监听和项目已保存端口。提交已发布目标沿用 service/container_port；提交发现的 host 目标时，服务端按当前项目及服务重新解析所选监听端点，再生成上游。扫描不写入项目设置，不触发部署。固定目标沿用现有绑定持久化及重部署跳过动态刷新逻辑，手动 host_port 仍按项目已保存列表校验。具体候选标识与字段在实现时保持前后端一致。
