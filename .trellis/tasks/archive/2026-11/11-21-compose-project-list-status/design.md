# 技术设计

## 列表状态和展开

- 保留现有项目列表接口和响应字段。列表加载后按项目复用 `GET /api/v1/projects/{id}/status`，让状态请求的加载和失败独立于项目列表。项目行与展开明细共用同一次读取结果。
- 基于容器运行与健康状态显示中文摘要。无容器、无法读取、未运行、部分运行和运行中分别显示，健康检查失败及正在重启的状态可见。完成部署、启停或重启后重新读取受影响项目，手动刷新更新整个列表。
- 项目行展示展开控件、启停、重启与编辑配置。根据容器是否运行切换启停，暂无容器时的启动复用现有首次部署动作。窄屏将项目操作换行，沿用页面表格的卡片布局。

## 容器日志

- 在现有容器状态结果中提供 Compose 返回的容器 ID。新增 `GET /api/v1/projects/{id}/containers/{containerID}/logs`，按项目查询容器并匹配 ID，再调用 `docker logs --tail 200`。响应保持 `{"log":"…"}`，沿用日志错误处理和环境变量值脱敏。
- 保留项目汇总日志接口和「更多操作」入口。日志抽屉可展示项目或指定容器的日志，刷新继续读取当前对象。同服务的多个实例通过容器 ID 分开。

## 删除和文件清理

- 给现有删除确认增加复选框。用服务端计算的项目目录显示实际删除位置，不接受客户端提交路径。将文件清理选项通过 `POST /api/v1/projects/{id}/actions/delete?remove_files=true` 传递，省略参数的调用继续保留文件。
- 目录使用面板根目录下的 `data/projects/<项目 ID>`。勾选后核对服务器上的实际目录边界，沿用卸载流程的约束，项目目录及其父数据目录为符号链接或项目目录中存在宿主机文件系统挂载点时给出失败原因。普通的 Docker 容器目录映射随容器移除结束，项目目录中的普通文件和子目录可以清理。
- 保留现有的 Compose 停止移除和域名解除流程。Docker 命令执行成功且相关域名绑定处理完成后，才执行已选的目录删除；返回文件清理失败时保留数据库项目记录。Compose 命令继续保留命名卷，项目目录之外的路径无需遍历。
- 删除结果复用后台操作状态。在申请确认阶段取消时不发起 HTTP 请求；操作失败保留原因，成功后从列表移除已删除项目。

## 实施边界

运行状态、日志和删除确认都落在现有容器项目页面，使用同一个任务，依次实施和验收。由现有项目 API 和持久化记录承载，无数据库迁移。
