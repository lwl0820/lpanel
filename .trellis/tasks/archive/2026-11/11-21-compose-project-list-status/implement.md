# 实施与验证

1. 为项目状态响应补充容器 ID，接入按容器 ID 读取日志，覆盖跨项目 ID 被拒绝、同服务副本日志独立和输出脱敏。
2. 改造项目列表显示状态及行内展开，调整常用操作位置，接入容器日志抽屉和状态刷新。在宽屏和窄屏核对按钮、展开、日志的独立加载和失败反馈。
3. 接入可选的文件清理，将项目目录提示和复选框放入删除确认。覆盖取消、默认保留、勾选清理、目录外文件保留，以及 Docker 或目录清理失败后的记录保留。测试文件与替身产物放在仓库 `.tmp`。
4. 运行 `go test ./internal/panel -run '^TestProject'`、`go vet ./internal/panel`、前端类型检查、ESLint、相关轮询测试和生产构建。浏览器验收聚焦容器项目页，核对重新部署、启停之后的状态变化及删除弹窗。
5. 在可用的隔离 Docker 环境运行同服务多个实例和文件清理验收，核对命名卷保留。使用替身时记录覆盖范围和待实机验收项。更新项目托管及前端 API 契约。
