# 静态网站创建流程设计

## 目录分配

后端在新建时使用现有网站 ID 生成规则。目录留空时在安装根目录下创建 `sites/<ID>/`。标准安装对应 `/opt/lpanel/sites/<ID>/`，位于运行版本目录之外，并与权限为 0700 的 `data/` 分开。只为新分配的内容目录设置允许 Nginx 读取和遍历的权限。手动指定目录沿用当前绝对路径和存在性校验，沿用原目录权限。创建时不生成首页，网站列表显示实际目录，用户将网页文件放入该目录。编辑已存在的网站时原目录回填并仍为必填。

## API 契约

在 `POST /api/v1/sites` 增加可选的 `binding: {domain, auto_certificate}`。`directory` 空白表示自动分配。沿用 201 和原有顶层网站字段，随创建绑定时附加 `binding` 和可选的 `operation`。如 HTTP 已生效但证书任务无法启动，返回已创建的网站、绑定和证书错误信息，前端提示从域名配置重试。`PUT /api/v1/sites/{id}` 和现有单独绑定域名入口保留原契约。

## 绑定与证书

复用共用域名校验、证书条款检查、Nginx 配置应用及回退。创建和绑定作为同一表单提交处理，绑定失败回收本次新建的网站记录。回收自动目录仅限本次分配且仍为空的目录。已存在的手动目录保留。绑定与 HTTP 生效后再提交现有证书后台操作，继续使用 HTTP-01、Nginx 生效校验与失败回退。证书状态由后台操作和域名记录提供。

## 前端交互

复用静态网站新建弹窗。目录留空提示会自动分配。新建表单添加可选域名，在填写域名时可选自动申请 HTTPS，并简短说明域名解析、公网 80 端口和证书服务条款。表单错误留在当前弹窗内。提交成功后刷新网站列表并显示已分配目录和域名。复用页面现有的长操作状态和消息，证书失败以现有域名证书管理入口重试。
