# 为 HTTPS 反向代理启用 HTTP/2

## 目标

让支持 HTTP/2 的客户端访问 LPanel 托管的编排项目和宿主机程序的 HTTPS 域名时，能够与 Nginx 协商使用 HTTP/2。域名绑定弹窗提供默认开启的 HTTP/2 开关，管理员可以按域名调整。

## 背景

[`renderNginx`](../../../../../internal/panel/domains.go) 为启用证书的绑定生成 TLS 监听。编排项目和宿主机程序共用转发配置，Nginx 以 HTTP/1.1 连接上游，并支持 WebSocket 握手。现有绑定可用 [`setup-nginx`](../../../../../docs/install.md#L100) 重新生成配置。

## 需求与范围

- 在编排项目和宿主机程序的新建和编辑绑定弹窗显示 HTTP/2 开关，默认开启，启用 HTTPS 后生效。已有绑定缺少该设置时也默认开启，保存过的设置在编辑时回显。
- Nginx 1.25.1 及以上支持逐域名开关。较旧且支持 HTTP/2 的 Nginx 默认开启，弹窗显示已开启并提示升级后可单独关闭。缺少 HTTP/2 支持的 Nginx 保留现有 HTTPS，弹窗说明当前不可用。
- 保持现有上游 HTTP/1.1 转发、代理请求头和 WebSocket 握手行为。原有明文 HTTP 入口、HTTPS 跳转和 ACME 验证照常工作。
- 沿用现有配置检查和生效流程，兼容项目支持环境中的 Nginx 版本。同一 HTTPS 端口上的其他站点应仍能正常访问。

## 范围外

为面板或静态站点单独开启 HTTP/2、变更上游协议、支持明文 HTTP/2。

## 验收条件

- 在真实 Nginx 中加载生成的配置，通过 `nginx -t`。分别覆盖支持环境中使用旧式 `listen` 参数的版本和支持独立 `http2` 指令的版本，并验证同一 HTTPS 端口上的其他域名仍能正常访问。
- 对启用证书的编排项目域名和宿主机程序域名发送请求，确认 TLS 协商结果为 `h2`，请求到达预期上游并返回正确内容。使用仅支持 HTTP/1.1 的客户端访问，普通请求成功且 WebSocket 握手返回 `101`。
- 对已有 HTTPS 绑定运行 `setup-nginx` 后复验 HTTP/2，无需重建绑定或重签证书。确认启用证书后原有 HTTP 跳转、ACME 验证路径以及未启用证书的 HTTP 域名仍可正常使用。
- 在支持逐域名设置的 Nginx 上关闭一个域名的 HTTP/2，重新编辑时保持关闭，且另一域名仍协商 `h2`。旧版 Nginx 上确认开关已开启且不可编辑，并显示升级说明。
