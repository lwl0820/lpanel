# 面板登录入口实施计划

1. 后端新增 `login_path` 与输入校验，接入 `init` 及已认证的访问设置，复用 Nginx 配置生效流程。确认进入、更新和清空都能持久化，并保留同机业务和证书配置。
2. 服务端实现启用入口时的页面、资源和登录请求处理，复用会话规则。处理经 Nginx 返回的真实 404，保留本机探针与 ACME challenge。
3. 在「面板设置」增加登录路径编辑和完整地址。登录页在提交前保留正确路径，成功后进入原路由，退出后重新请求服务器。核对概览或证书变更提示中展示的面板地址。
4. 安装脚本补齐交互、`--login-path`、旧发行包兼容、自检与结果地址。同步安装及维护说明。

## 验证

- 运行受影响的 `cmd/lpanel` 和 `internal/panel` 下的配置、登录、会话及 Nginx 相关测试。主要覆盖错误入口真实 404、登录成功、过期、路径更换和禁用。
- 运行 Bash 语法检查及 `tests/install-smoke.sh` 中受影响的安装场景。检查交互回车、无人值守、指定路径、无效路径和旧发行包分支。
- 运行前端类型检查、lint、相关 API 和路由测试及生产构建。用真实浏览器和隔离 Nginx 验证登录资源能加载、错误入口直接返回 404、登录后正常刷新页面、重启保留配置和更换入口。隔离环境核对安装、升级探针以及 ACME 挑战路径。
