# 实施与验证

1. 梳理 `app.go` 的启动兼容刷新与 `domains.go` 的托管配置生成，在不改动现有安装入口的前提下增加模板修订号，移除以两个 `location` 判断是否需要刷新的逻辑。
2. 在目标程序的启动健康检查之前接入配套操作。对升级期间的刷新错误阻断健康成功，保留对普通重启和缺失、非托管配置的现有处理。通过现有升级操作记录和 systemd 日志提供失败原因。
3. 让新升级工作进程仅在候选配置已改变且版本回退时恢复上一份托管配置，保持现有数据库、业务文件和证书布局。验证健康检查超时后仍能执行恢复。
4. 运行与面板升级、Nginx 配置生效和回退相关的定向 Go 测试。回归覆盖包含旧两条规则但缺少修订号的托管配置、成功后再启动、未托管配置及检查、重载、回读的故障分支。
5. 在隔离环境用 `v0.1.24` 作为升级源，运行真实 Nginx 和面板升级。通过已有 HTTPS 绑定验证协议、登录和代理规则。验证失败时上一版可用，记录实际 systemd 与替身的覆盖范围。
6. 更新安装、升级和验收文档。将升级后的 `setup-nginx` 从常规步骤改为排障命令，并说明后续变更在哪里登记配套操作及如何验证。
