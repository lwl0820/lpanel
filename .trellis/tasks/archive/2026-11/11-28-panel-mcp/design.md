# 技术设计草案

通过现有面板 HTTPS 入口提供独立的 MCP HTTP 路由，保持 Go 服务的回环监听。入口要兼容面板自定义登录路径和 Nginx 代理；设置页展示客户端应使用的外部地址。

管理员设置接口沿用 RequireAuth。SQLite 保存开关和独立的令牌记录；使用安全随机数生成令牌，只保存摘要，明文仅签发时展示一次。每次 MCP 请求检查开关和 Bearer 令牌，覆盖初始化、发现工具、调用及查询结果。关停或撤销影响后续请求，已经提交的业务操作沿用原有生命周期。

首版使用 Streamable HTTP 对接客户端。每个工具定义明确的输入和返回值，调用面板已有业务逻辑，沿用其参数校验、错误及异步操作记录。仅注册需求表中的业务工具，管理员设置接口独立于工具注册。宿主机文件工具沿用原有路径规则，每枚令牌均可访问管理员文件工具可操作的路径。

采用新增数据结构，旧安装缺少 MCP 配置时视为关闭。上线后可通过设置页关闭入口。验证时从实际面板代理地址连接，检查正常响应和错误均不泄露令牌。

公网入口固定为 `/api/v1/mcp`，与已有自定义登录路径兼容。用户确认首版暂缓调用限流。
