# 服务器管理面板技术设计

## 架构与取舍
浏览器访问宿主机 Nginx；Nginx 直接提供 Vue 构建产物，并把 /api/ 转发到仅监听回环地址的 Go 服务。Go 使用标准库 net/http，不增加独立网关或应用框架。前端采用 Vue 3、TypeScript、Vite、Element Plus，直接导入组件，先使用局部响应式状态和统一 API 调用，不预设全局状态框架。

使用 database/sql 与 modernc.org/sqlite 保存单管理员、会话、项目、网站、域名绑定和操作记录。不需要额外数据库服务、ORM、Redis 或消息队列。确切依赖版本在基础框架阶段核对兼容性并写入锁文件。

面板需管理 Docker、Nginx 和证书，systemd 服务以 root 运行，后端只监听回环地址；所有管理接口要求登录，密码使用 bcrypt 散列，会话使用随机令牌和 HttpOnly、SameSite Cookie；启用 HTTPS 后设置 Secure。只实现单管理员，不引入权限体系。外部命令使用参数数组执行，输入不能作为 shell 片段执行。

## 代码组织
- cmd/lpanel：服务启动、管理员初始化与独立升级工作入口。
- internal：按账号、持久化、项目、网站、域名证书、升级组织实际模块；不提前创建多层接口和单次使用的工具包。
- web：Vue 页面、共享 API 类型与客户端、构建配置。
- deploy：一键安装、systemd 单元、Nginx 模板及证书续期钩子。
- scripts：验证及发行包构建脚本。
- tests：需要宿主机服务的集成验证。所有临时产物写入工作目录 .tmp。

业务逻辑尽量留在一个清晰的函数中；只有被多个入口实际使用或边界复杂时才提取公共函数。域名及证书是面板、项目和网站之间的实际复用边界。

## 安装与持久化布局
安装根目录 /opt/lpanel，systemd WorkingDirectory 使用该目录。
- releases/<版本>/lpanel、web/：完整版本发行包，包含同一版本的后端和前端。
- current：指向运行版本的符号链接。
- data/panel.db：持久化数据；data/config.json：内部监听地址、面板端口、域名和发布源等启动配置。
- data/projects/<标识>/：compose.yaml 与 .env；相对挂载和构建上下文以项目目录为基准，用户需在服务器准备对应文件，首版不提供源码上传。
- data/acme/：Certbot 账户和证书；data/logs/：操作与证书日志。
- acme-webroot/：供 Nginx 读取的公开验证文件目录，与权限为 0700 的 data 分开；安装根目录和前端版本目录须允许 Nginx worker 遍历。
- .tmp/：下载、候选配置、升级与 Certbot 工作文件；子进程 TMPDIR 同样指向此处。

Nginx 的面板管理配置独立命名存放于系统 include 目录；只写面板拥有的文件。静态网站内容保留在用户指定的服务器目录，删除网站不删除该目录。项目删除通过 compose down 移除容器与网络，不使用 --volumes，也不删除挂载目录。

## 数据及接口边界
核心实体采用简单关联：管理员和会话；项目（原始配置、环境变量、状态）；网站（目录、路由回退）；域名绑定（资源种类、资源标识、目标服务端口、上游协议、是否自动证书、证书状态与到期时间）；操作记录（类型、状态、日志、错误）。端口解析结果是 Compose 配置的派生结果，运行端口以 Docker 实际发布结果为准。

/api/v1 下提供以下接口组：auth（登录、退出、当前用户）、projects（配置、扫描、部署和生命周期、状态日志）、sites（目录与绑定）、bindings（域名与证书申请/重试）、operations（进度结果）、system（面板访问设置、当前版本、检查更新、发起升级）。字段使用统一类型，错误返回可识别错误码和中文说明；密码、会话和环境变量秘密不进入普通日志或非必要响应。

长耗时部署和签发请求返回操作标识，服务内执行命令并记录状态，前端轮询；不引入队列服务。升级结果由独立工作进程写入可持久化结果，服务重启后前端仍可读取。普通中断操作启动后标记为失败并允许用户重新发起，升级操作以工作进程结果为准。

## Compose 到域名的数据流
1. 保存用户原始 Compose 和环境变量；用 docker compose config --format json 校验并规范化，解析变量和短/长端口格式，不自行重写 Compose 语义。
2. 返回服务、容器端口、宿主机发布端口、绑定地址、TCP/UDP 及来源 ports/expose。没有发布端口的项仅展示说明；不自动改写用户配置。
3. 管理员选择服务和已发布的 TCP 端口，并指定上游 HTTP 或 HTTPS；不能根据端口号可靠推断应用协议。UDP 不能选作网站代理。
4. compose up -d 后读取实际端口映射。通配绑定转换为回环目标，指定地址使用实际可达地址；动态发布端口在部署后解析。项目重新部署后刷新对应代理目标。
5. 生成 Nginx 代理配置，支持 WebSocket。用户选择的服务若不是 HTTP 类服务，明确返回访问或代理错误，不承诺通用协议转发。

## Nginx 与 HTTPS 数据流
面板入口使用用户端口（默认 8443）；未签发前为 HTTP，签发成功后同端口改为 HTTPS，最终地址携带配置端口。为简化同端口协议切换，旧的 HTTP 地址在成功后不承诺继续可用。业务域名使用 80/443；同一个面板 Nginx 可承载多个业务域名。全局域名绑定保持唯一，避免两个资源争用同域名。

所有受管理域名的 80 端口配置均保留 /.well-known/acme-challenge/ 的文件访问路径，使用统一验证目录。验证路径优先于 SPA 回退和 HTTPS 跳转。面板使用自定义端口时仍生成其 80 端口验证入口。

勾选自动证书：先生成可用 HTTP 配置，再调用 certbot certonly --webroot；成功后引用保存的证书生成 HTTPS 配置。状态依次为未启用、申请中、已启用或申请失败；只有证书存在且 Nginx 配置生效才标记已启用。首次失败保留 HTTP，已有有效证书续期失败则保留当前 HTTPS。

配置写入先保存旧版本，检查 nginx -t 后重载；失败恢复受管理的旧文件并记录错误，不修改外部站点。共享配置修改在进程内顺序执行，不增加分布式锁。

使用一个面板管理的 systemd timer 调用 certbot renew，避免和其他续期任务重复。续期部署钩子检查配置并重载 Nginx。证书账户/证书目录固定，面板读取证书实际到期时间并显示最近操作结果，不靠一次成功状态推断永久有效。

## 一键安装流程与兼容性
验证矩阵为 Debian 12/13、Ubuntu 22.04/24.04/26.04 LTS，均覆盖 amd64/arm64、systemd 和 apt。具体可支持声明以实际验证结果为准，不自动扩展至其他派生发行版。

安装按 root 权限执行：检查系统架构、已有环境和端口；交互获取管理员、隐藏输入密码、端口、可选域名与证书选项；下载同架构发行包；安装缺少的 Nginx、Certbot 和可用的 Compose v2；初始化配置与管理员；启动后端及 Nginx；可选签发证书；验证实际访问地址并输出结果。

已有 Docker 通过 engine、compose 命令能力检查后复用，不为了换包源卸载已有环境。非面板管理的 Nginx 或监听端口冲突时停止相关步骤并给出原因，不接管。脚本重跑应识别本面板布局并保留现有管理员和业务数据，不能重新初始化覆盖；后续版本更新走升级流程。

管理员密码通过标准输入交给初始化命令，不出现在命令行参数和终端回显。证书账户注册所需联系信息由设置支持，安装不得因遗漏一个未约定的必填邮箱而卡住；无邮箱注册使用 Certbot 支持方式，明确接受 CA 条款后申请。

## 发布与升级
固定发行契约为版本标签 vX.Y.Z，附件 lpanel_vX.Y.Z_linux_amd64.tar.gz、lpanel_vX.Y.Z_linux_arm64.tar.gz，每包包含 lpanel、web/ 和所需 deploy/ 文件。校验文件随发行包提供，用于发现下载损坏；不新增签名基础设施。发布脚本只构建产物，不在当前未授权的情况下对外发布。

发布源配置 owner/repo；每天及手动访问最新正式 Release，按语义版本比较，不将源码归档、草稿、预发布或普通字符串排序当成更新。未配置、限流、断网和缺失架构附件分别给出可识别结果。

用户点击升级：下载并检查发行包，解压到新 release；通过 systemd-run 启动同一程序的独立 upgrade-worker，保留旧 current 目标；工作进程切换 current、重启 lpanel 服务，检查本地健康和版本。失败切回旧 current 并重启，写入升级结果。工作进程不属于面板主服务的进程组，避免服务重启把升级一起终止。

业务数据放在 releases 外，升级不重建网站、容器和证书。首版 schema 变更仅采用旧程序仍可读取的增量方式；破坏性数据迁移不在本次自动升级机制范围内，不能只回退程序却留下无法读取的数据库。

## 验证与待运行确认
纯逻辑和 API 用自动化测试。本地可运行的 Docker、Nginx、证书和升级路径用隔离环境验证，发行包构建与目标架构运行分别记录。依赖公网域名或当前本地缺少的目标系统和架构时，记录待人工验收的前置条件和预期结果。详细顺序及命令见 implement.md。
