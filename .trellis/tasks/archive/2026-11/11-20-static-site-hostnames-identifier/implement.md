# 静态网站创建与编辑实施计划

## 实施顺序

1. 修改 `internal/panel/sites.go` 的网站持久化与 API。加入备注、网站标识唯一约束和旧数据迁移，按标识生成默认目录。复用现有网站 ID 和目录权限。
2. 调整 `internal/panel/sites.go` 和 `internal/panel/domains.go` 的创建、绑定和签发流程。复用普通域名校验，增加静态网站通配符 HTTP 绑定，统一校验并保存同一次创建的全部主机名，在全部 HTTP 绑定生效后发起普通域名证书任务。核对数据库、目录和 Nginx 配置的失败恢复。
3. 更新 `web/src/sites-api.ts` 和 `web/src/views/SitesView.vue` 的字段、多行输入、备注及证书反馈。同步「域名与证书」和绑定弹窗中的网站标识显示、通配符证书入口与提示。
4. 更新网站已有回归用例，仅补充旧数据迁移、多绑定整批回滚、默认目录碰撞与混合证书结果等现有用例无法覆盖的场景。完成定向验收后，将验证过的行为写入项目契约。

## 验证

- 后端运行 `go test ./internal/panel -run 'Test(Site|Binding|Domain|Nginx|ACME|Certificate)'`，根据实际变更补选受影响的已有绑定用例。核对重名旧网站升级、备注保存与清空、目录分配、主机名失败回滚、普通域名证书部分失败及通配符证书请求被拒绝。Go 缓存和测试临时目录使用工作区 `.tmp`。
- 前端运行 `npm --prefix web run typecheck`、`npm --prefix web run lint` 和 `npm --prefix web run build`。浏览器核对多行输入、标识默认值与覆盖、保存失败后保留输入、备注编辑及混合主机名的证书提示。
- 在隔离环境验证同一网站的两个普通域名和通配符都能读取同一份页面，使用具体的子域名发出请求。证书使用已有替身或测试 CA 核对逐域名显示、部分失败保留 HTTP。区分本地实测、替身和依赖公网的验收范围。
