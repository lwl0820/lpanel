# 静态网站创建与编辑设计

## 网站数据与默认目录

- 网站接口使用 `identifier` 和 `note`，内部 ID 继续作为关联和编辑地址的一部分。列表、编辑标题及域名管理中的网站选项使用网站标识。备注保存在网站记录中，允许为空。
- 数据库沿用原 `name` 列保存网站标识，新增默认值为空的备注列，并对标识建立唯一索引。启动迁移在同一事务中处理旧记录并建立索引。已有重名按稳定顺序保留首条旧名称，为其余网站生成不与已有标识冲突的后缀。已有网站 ID、目录、域名绑定和证书保持原状。
- 标识去掉首尾空白，唯一性按存储值比较。长度上限至少覆盖现有校验允许的最长主机名。目录留空时，服务端从标识生成一个目录名，保留常见文件名字符和中文，将路径分隔符、控制字符及文件名或 Nginx 配置不支持的字符换成 `_`，并处理 `.` 和 `..`。默认目录位于 `Root/sites/`。自动生成的目录已存在时提示修改标识或填写已有目录。编辑标识时沿用已保存的目录。手动指定目录沿用绝对路径及存在性校验。

## 主机名与创建结果

- 新建请求以 `hostnames` 数组提交主机名，保留输入顺序，另外提交 `identifier`、`directory`、`spa`、`note` 和可选的 `auto_certificate`、`acme_account_id`。前端按换行拆分，服务端去掉首尾空白和尾随点，统一主机名大小写，检查有效性、重复和已有绑定。省略标识时用第一个主机名作为默认值。
- 普通域名沿用现有校验。仅静态网站接受最左一段为 `*` 的域名。Nginx 使用现有的 `server_name` 渲染，显式绑定的域名优先匹配。网站列表显示通配符文本，具体域名继续显示可打开的链接。通配符使用 HTTP，证书入口按此状态提示，服务端在提交证书任务前检查是否适用。[Nginx 主机名](https://nginx.org/en/docs/http/server_names.html) · [Let's Encrypt 验证方式](https://letsencrypt.org/docs/challenge-types/)
- 创建网站并绑定主机名时，复用现有绑定校验和写入逻辑，避免每个域名单独重载 Nginx。先检查全部主机名及适用的证书账户，再在现有域名操作锁内将网站与绑定写入 SQLite。数据库提交后应用一次 Nginx 配置，以便现有配置生成查询读取整批绑定。配置失败时沿用旧配置恢复流程，再回收本次记录及本次创建且仍为空的目录；自定义目录及其中的文件保留。单独添加域名仍沿用原入口和响应。

## HTTPS 与编辑

- HTTP 生效后，创建接口返回网站、已建立的 `bindings`、可选的 `operation` 或证书任务启动错误。为普通域名开启一个后台操作，逐个调用现有签发函数，收集各域名的结果。签发失败时保留该地址的 HTTP，继续处理其他域名。操作结束后前端刷新域名状态。任务启动失败时保留网站和所有绑定，提示可在「域名与证书」重试。
- 表单的自动标识跟随第一个非空主机名，手动覆盖后沿用手动值。纯通配符时说明 HTTP 状态；混合输入时说明自动 HTTPS 适用的域名。证书提示、进度和错误沿用现有组件。编辑只提交网站元数据，允许无域名的旧网站直接保存备注。网页目录或单页应用配置有变化时，同步已有绑定并应用；仅修改标识或备注时直接保存。
