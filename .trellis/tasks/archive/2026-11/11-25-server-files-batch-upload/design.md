# 文件管理增强设计

## 选择、复制与移动

在现有文件列表按绝对路径记录勾选项，切换目录时清空勾选。用户执行复制或剪切时单独保存源路径和动作，跨目录导航后仍可点击“粘贴”。列表工具栏和单行菜单复用同一操作。删除沿用已有确认与服务端删除规则，批次结果列出失败项和原因。

复用现有单项删除接口。复制、移动和属性修改也按条目调用，界面汇总结果。复制目录保留目录结构，遇到链接仅复制链接本身。复制和移动均保留已有同名目标，并拒绝将目录粘贴进自身或下级。剪切成功的条目从待粘贴列表移除，失败项保留。跨文件系统移动须在目标复制完整后才删除来源；若来源清理失败，报告实际结果。

## 权限与所有者

目录列表补充权限、所有者的信息，兼容已有列表字段。操作框回显现值，分别提交权限或所有者。权限使用 Linux 权限位，所有者按宿主机用户解析。批量设置权限只作用于选中的条目。对符号链接的操作不得意外修改所指文件；系统不支持修改链接自身权限时按项告知。沿用管理员会话与现有文件类型约束。

## 三个上传入口

选择文件、拖入、粘贴均在动作发生时取得文件列表和当前目录，再交给同一上传流程。接收区域包含空目录。处理原生粘贴事件时优先使用浏览器交付的文件，单次事件只执行一种操作；面板“粘贴”按钮始终使用已复制或剪切的服务器条目。编辑文本、输入名称时保留原生文本粘贴。只把实际收到的文件交给上传接口。文件管理器和浏览器组合能否提供原始文件名与字节，需要真机验证。[浏览器事件参考](https://developer.mozilla.org/en-US/docs/Web/API/DataTransfer/files)

## 分片传输与进度

在现有管理员文件 API 下增加创建上传、提交分片、完成和放弃上传的接口。创建时提交目标路径和文件大小，返回上传标识与分片大小。首版建议每片 512 KiB，前端按字节偏移顺序发送原始内容。服务端校验偏移并返回已接收字节数；前端据此更新每个文件的进度。零字节文件直接进入完成步骤。用户可看到具体哪个文件失败。

服务端将分片写入暂存文件，收齐声明的字节后以不覆盖已有项的方式发布目标。完成请求成功后再显示“已上传”。失败或放弃时清理本次暂存数据。旧整文件接口继续服务已有调用方。新入口在有限请求体配置下验收，无需扩大业务站点的请求体限制。回退时先恢复前端旧入口，再撤下新接口。
