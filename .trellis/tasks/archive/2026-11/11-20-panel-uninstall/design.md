# 卸载设计

## 脚本入口

安装与卸载分开。下载安装脚本运行后从终端读取账号等设置；下载独立卸载脚本后从同一终端读取确认。卸载脚本可以直接用于 v0.1.0 的标准安装，使用已安装版本的文件和配置，不依赖面板接口或升级。

README 提供从项目 GitHub 下载独立脚本并使用 sudo 运行的命令，详细影响在安装文档说明。上线时需要 GitHub 默认分支包含该脚本。

## 资源边界

卸载针对官方安装布局。用已安装的面板程序或面板单元确认存在安装，并核对配置文件首行已有的 LPanel 管理标记。只处理 `/etc/systemd/system` 下本项目的三个固定单元文件、标准 `/etc/nginx/conf.d/lpanel.conf` 和 `/opt/lpanel` 下的版本指针及发行目录。非标准部署使用其原有管理方式处理。

`lpanel.conf` 同时承载面板、静态网站和容器应用的域名入口，移除会让这些入口停止提供原业务。续期随定时器停止，已签发证书及私钥留在原路径。

## Compose 清理选项

默认保留容器、网络、项目目录和配置。管理员选择清理时，用官方安装已带的 Python 3 从 `data/panel.db` 的 `projects` 表读取项目清单，按登记的项目 ID 和项目目录匹配面板使用的 `lpanel-<ID>` 项目名。展示将清理的项目和绝对目录，明确目录内数据会被删除，再读取最终确认。按现有项目删除的 Docker 参数 `docker compose ... down --remove-orphans` 清理，沿用 `data/projects/<ID>/compose.yaml`、`.env` 和工作目录。避免按名称前缀遍历服务器项目，也无需启动面板或依赖新版本的 CLI。

Compose 清理成功后删除项目目录，包含其子目录、项目文件和相对挂载的数据，随后从数据库中移除项目记录及标记为该项目的域名绑定。目录路径由有效项目 ID 和固定的项目根目录构成，清理只移除目录内符号链接本身。镜像、Docker 卷、目录外的数据、未登记的目录和其他类型的面板记录保留。若项目文件缺失或 Docker 命令失败，提示失败项目并停止卸载流程，保留该项目的目录及记录供重试。若目录或记录清理失败，报告失败路径或项目并停止，不宣称完成。

## 执行顺序

1. 检查权限、安装状态和受管理配置，询问是否清理 Compose 项目，展示所选范围并读取最终确认。
2. 停止面板和续期进程，停用开机启动与续期定时器。
3. 按选择逐一清理 Compose 项目。
4. 将面板 Nginx 配置移出加载位置，执行 `nginx -t`。Nginx 正在运行时重载。失败恢复文件并给出重试提示，保留面板程序供处理。
5. 移除面板单元文件与程序版本，执行 `systemctl daemon-reload`，提示保留数据的位置。复跑仅清理尚未移除的面板资源。

脚本验证使用隔离环境和工作目录下的临时文件。业务或面板升级进行中时应先等待结束。
