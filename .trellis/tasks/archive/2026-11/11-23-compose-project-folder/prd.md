# 使用项目名称作为新建 Compose 项目的目录名

## 目标

管理员可以按名称找到新建项目的文件，删除后同名重建可以复用保留的业务数据。已有部署升级后继续在原路径运行。

## 要求与验收

- **新建。** 项目名去除首尾空白后为 1 至 100 字节，可直接作为 Linux 单个目录名。拒绝含斜杠、NUL 的名称及单独的点或双点。已登记项目的同名或同路径会阻止创建。未登记的同名目录可以复用。例如创建 ghost-blog 后，实际目录为 data/projects/ghost-blog/。
- **升级。** 旧表仅存 ID、名称、配置、环境变量和更新时间。升级自动按 ID 回填旧路径，保留项目记录、文件、容器标识和挂载。旧名称重复或含新规则禁止的字符也能升级并继续管理；重复启动结果一致。
- **编辑。** 旧项目修改配置或显示名称后仍使用回填的路径。按名称创建的项目改名后，记录和实际目录与新名称一致；已登记项目独占其目录。
- **删除。** 未勾选删除文件时，在 Compose down 成功后删除根目录的 compose.yaml 和 .env，保留目录、其他文件及相对挂载数据。勾选时沿用整目录清理范围。界面明确告知两种选择的结果。
- **恢复。** 默认删除后，用原名称重新创建并提供配置和所需环境变量，可直接使用保留的业务数据。若未登记目录本来就有 compose.yaml，允许使用该配置和已有的 .env 恢复，扫描与部署使用一致的内容。
- **范围。** 此次只调整面板管理的 Compose 项目目录及相关操作。旧项目的目录命名、Docker 命名卷与目录外数据沿用现状。
