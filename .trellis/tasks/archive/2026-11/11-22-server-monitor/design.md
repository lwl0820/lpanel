# 服务器状态监控设计

首页单独请求宿主机摘要，不将它并入项目、网站、证书的成组请求。详情按需请求各磁盘、实时进程以及所选时间范围的历史。所有读接口沿用 `App.RequireAuth`。本模块可直接从现有首页进入，不依赖服务器设置页面。

## 实时读数

从 Linux 的系统统计读取 CPU 的累计时间，以两个读数的增量计算使用率；内存已用量按总量减可用量计算。容量按本地文件系统的挂载位置读取，系统盘取 `/` 所在的文件系统。进程行使用名称、进程号、常驻内存及 CPU、磁盘读写计数；利用同一进程的相邻读数与实际经过时间计算速率。新进程或缺少读数时不显示伪造的零值。只在实时明细需要时读取进程；用于差值的计数留在内存，不写入历史。

## 整机历史

采样随 `App.Serve(ctx)` 运行，不在其他终端命令也会调用的 `Open` 中启动。每分钟将实际采样时间、整机 CPU、内存和各磁盘空间写入现有 SQLite；时间用统一时间戳，磁盘用挂载位置区分。一次提交一个时点的数据，按采样时间查询及清理；服务恢复后继续清理超过滚动 30 天的记录。后台不采集进程榜单，不需要新增外部监控服务。

趋势按时间顺序返回实际样本；停机、采样失败或磁盘不在场时不补零，图表不跨空档连线。回退面板版本时停止采样即可，不删除已有样本，也不改宿主机设置。
