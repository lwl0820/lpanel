# 实施与验收顺序

| 阶段 | 交付工作 | 通过条件 |
| --- | --- | --- |
| 1. 程序与运行 | 增量建表，接入 Supervisor 和 B 版列表与详情分栏；完成目录、运行用户、入口、参数、启停和状态。处理依赖提示与安装说明 | 在隔离 Linux 主机运行一个输出日志且监听 TCP 的小程序，验证手动停止、异常重启及错误入口，另用无 Supervisor 环境打开原有面板功能 |
| 2. 文件、复制与日志 | 把「打开目录」接到现有文件管理，在启动设置处理选定入口的执行权限；完成复制及日志跟踪，核对日志流的 Nginx 配置 | 从程序详情打开正确目录，用现有文件管理上传主程序，回到启动设置指定入口并启动，在详情的「运行日志」内连续收到新行。复制后验证内容一致、目录独立、初始停止 |
| 3. 运行监控与域名 | 对接按程序采样、端口归属，在现有绑定弹窗、域名列表及 Nginx 渲染中识别程序目标，沿用证书申请与续期；完成删除关联资源与卸载策略 | 从监听端口完成绑定，验证 HTTP、WebSocket、HTTPS、停启及解绑，对照现有 Compose 和静态站点访问结果 |
| 4. 升级与验收 | 从现有 LPanel 版本升级，检查已有编排项目、域名和证书，再用新建程序完成端到端验收 | 留存运行和文件归属、访问、删除保留及版本回退结果，记录真实证书验证环境 |

## 验证安排

- 后端按新增用例和受影响功能运行，例如新增 Program 系列用例后执行 `go test ./internal/panel -run 'Program|ProjectBinding'`。重点覆盖复制后误启动、入口文件执行权限、现有绑定兼容和删除只影响本程序。
- 对照 B 版原型验证桌面分栏和手机横向程序列表。在两个输出不同日志的程序间来回切换，检查详情标题、日志、端口和操作对象一致。进入启动设置并返回日志，确认显示当前程序的输出。
- 前端执行 `npm --prefix web run typecheck`，仅运行新增程序交互、路由和受影响域名接口的测试。浏览器通过面板端口核对从详情跳转文件管理的目录、单文件上传后启动、日志增长，以及从两个入口打开同一绑定弹窗并查看证书状态。
- 更改部署脚本时分别执行 `bash -n deploy/install.sh` 和 `bash -n deploy/uninstall.sh`；在隔离实例检查更新、依赖缺失和卸载保留。项目内测试临时文件使用 .tmp/。
- 真实 Supervisor、Nginx 和公网签发分别验收。记录命令替身、真实服务与受控域名的实际覆盖范围。
