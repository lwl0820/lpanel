# 程序托管融合设计

## 依据

对照 SupervisorPanel 的 main（619f6fa）和 LPanel 的 main（aff3f8b）。前者的 internal/supervisor/client.go 定义运行配置与启停，internal/server/server.go 及 web/src/api/projects.ts 定义文件、复制和日志接口，internal/monitor/collector.go 提供按进程采样。LPanel 的 internal/panel/projects.go 直接管理 Compose；domains.go 的 Binding 已用 kind 与 resource_id 区分资源，server_files.go 处理宿主机绝对路径，project_listeners.go 将进程文件描述符与 TCP 监听表关联。

## 托管边界

建议继续使用 Supervisor，便于沿用源项目的启停、日志与异常重启语义。LPanel 自身仍由 systemd 管理。将 Supervisor 作为可选宿主机依赖，在模块入口检测并说明安装条件。使用独立的配置名前缀和程序 ID，变更只对指定程序生效，已有 Supervisor 配置保留原管理方。

新增 SQLite 程序表，记录稳定 ID、显示名、入口相对路径、参数和运行账户；工作目录按 ID 放在 Root/programs/ 下（Root/data 以 0700 保护数据库，程序运行用户需要能遍历业务目录），改名不移动文件。建议默认使用已有非特权账户，明确展示最终运行身份。程序用户需要能遍历目录和读取文件，创建需要写入的数据目录时也应按该用户验收权限。新建和复制后均由管理员首次启动。运行中变更入口、参数或账户时，界面说明何时重启应用配置。

## API、文件及日志

建议以 /api/v1/programs 作为程序资源入口，提供启动配置、启停、复制、运行信息和日志，共用 LPanel 管理员会话及错误格式。详情返回已登记的工作目录，「打开目录」通过 Vue Router 跳转到 /server/files，使用 path 查询参数传入绝对路径。ServerFilesView 已支持按此参数打开目录，文件操作全部走现有 /api/v1/server/files 接口。

启动设置接受相对于工作目录的主程序路径。现有上传接口以 0666 模式创建普通文件，上传的二进制缺少执行位。建议在保存启动设置时明确提示将为指定主程序赋予执行权限，操作仅适用于工作目录内实际选定的普通文件。复制首版建议跳过符号链接并展示数量，日志和域名为各程序独立资源。

Supervisor 提供状态、PID 及独立输出；结合已有 procfs 采样按 PID 展示 CPU、内存，复用套接字归属识别端口与连接数。首版按主进程采样，页面说明统计口径。停止或读取失败显示相应状态。日志先读最近若干行，再用 SSE 跟踪新增内容，日志查询走程序接口，面板 Nginx 的日志流路径需支持实时输出。

## 域名接入与升级

给 Binding 增加 program 类型，resource_id 指向程序 ID，使用所选监听地址、端口与协议构造上游。BindDomainDialog 在现有目标选择器中列出程序，支持从程序详情预选程序和端口；DomainsView 展示绑定归属。复用现有绑定接口和 Binding 存储，在目标校验及 Nginx 上游渲染处识别 program。证书申请继续使用现有账户选择器、请求接口和续期任务。沿用全局域名唯一、证书申请及续期、WebSocket 转发和配置应用失败恢复流程。程序停止期间保留绑定配置，恢复到原监听端口后可继续访问。

升级使用增量建表并兼容旧绑定。删除程序按现有项目的习惯默认保留业务文件，先清理该程序的代理和托管配置，再移除记录。需在卸载脚本中列明默认保留项和主动清理项。旧版 LPanel 无法解释 program 绑定，版本回退前先用新版解除新增绑定并备份数据库和配置。

## 已确认的 B 版界面

[交互原型](research/ui/preview.html#b) · [桌面预览](research/ui/b.png)

桌面左栏显示程序名称和状态，选中项持续高亮。右栏顶部放程序名称、状态、启停和更多操作，中部显示 PID、CPU、内存、TCP 连接数，随后是监听端口及「打开目录」。下方默认显示「运行日志」，同一位置可切换至「启动设置」。文件与域名入口沿用前述现有模块。

切换程序时以新程序 ID 加载详情，并结束上一程序的日志跟踪。手机上把程序列表移到详情上方，使用横向滚动选择程序。新建入口位于页头，已有程序和空列表均可使用。
