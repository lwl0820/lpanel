# 多提供商 ACME 账户设计

## 现状与边界

现有 Certbot 同时负责签发和定时续期，证书按域名保存在安装根目录的 `data/acme/live/`，Nginx 直接读取该路径。全局邮箱、条款及可选 CA 地址存在 `Config`，面板、Compose、静态站共同调用 `RequestCertificate`。本次保持 Certbot、Nginx webroot 和原 systemd 定时器，通过账户 ID 选择签发配置。 [签发和续期](../../../internal/panel/domains.go) · [现有配置](../../../internal/panel/config.go) · [续期服务](../../../deploy/lpanel-renew.service)

## 账户与提供商

- 提供商包含稳定标识、显示名称、固定 ACME 地址、条款链接和是否需要账户绑定凭据。内置 `letsencrypt` 与 `zerossl`。Let’s Encrypt 使用正式签发地址；ZeroSSL 用免费 ACME 服务，需要用户从其账户取得 Key ID 和 HMAC 密钥。 [Let’s Encrypt 官方文档](https://letsencrypt.org/getting-started/) · [ZeroSSL ACME 文档](https://zerossl.com/documentation/acme) · [ZeroSSL 服务条款](https://zerossl.com/legal/terms)
- 账户保存 ID、显示名称、提供商、联系邮箱和条款确认状态。后台用现有 SQLite 持久化账户。提供商创建后固定，用户可另建账户并重新选择。列表返回可选账户及默认账户 ID，列表为空时默认 ID 为 `null`。
- 默认选仍存在且最早创建的账户，读取时按稳定顺序确定，省去额外的默认配置字段。这样安装创建的账户、HTTP 安装后添加的首个账户，以及删除默认账户后的替代账户都遵循同一规则。默认账户待补配置时，选择器提示补充信息，用户仍可手动选择其他账户。
- 删除接口在后端检查已启用绑定的签发账户及对应 Certbot 目录下仍保存的证书，覆盖旧安装的证书目录。存在任一证书时返回 `409` 并提示「此账户还有已签发的证书，无法删除」。检查覆盖换下、已过期及已解除域名绑定但仍存在的证书。与签发共用现有域名操作锁，删除检查通过后才移除账户记录，下一次读取时按创建顺序确定默认账户。当前解除域名绑定流程保留证书。
- 提供商信息随账户接口返回，凭据只写不读。配置 ZeroSSL 时可用账户专属目录注册 Certbot 账户。通过仅管理员可读的临时 Certbot 配置传递密钥，在工作目录内创建并在调用后清理。后续签发和续期复用 Certbot 已保存的本地账户。账户注册失败时返回可操作的中文提示，允许重新录入凭据。 [Certbot 配置与 EAB 参数](https://eff-certbot.readthedocs.io/en/stable/using.html#configuration-file)
- 升级时，将旧版已保存的证书配置或现有证书映射为既有账户，继续读取原证书目录。已有自定义 ACME 地址的安装保留原地址。没有证书配置的旧安装以空账户列表开始。迁移仅执行一次，删除账户后重启也不会恢复旧账户。保持旧 `bind-panel --acme-server` 和已有访问设置接口兼容。

## 签发、切换和续期

- 新账户通过 ID 取得独立的 Certbot 配置目录和证书路径，沿用域名作为 Certbot 证书名称。这样两个账户即使同时管理同一域名，候选证书也不会覆盖当前 HTTPS 正在使用的文件。旧证书仍从原路径读取。无新账户标识的已签发记录继续由原目录续期。
- API 请求使用 `acme_account_id` 表示本次选择。后端在公共申请流程校验账户可选且已同意对应条款。域名绑定请求、网站新建请求和手动申请请求都将该 ID 传入签发操作。无显式选择时优先使用证书原账户（如果仍可选），其次使用默认账户。两者都没有时，申请入口提示先新建账户。绑定响应使用只读的 `certificate_account_id` 表示当前证书的实际账户。
- 共用后台操作展示申请进度。首次签发后先核对证书，再应用并回读 Nginx 配置。换账户时同样等待新证书及 Nginx 配置通过后才切换实际账户；失败保留上一张证书、到期时间和续期归属。保持面板 HTTPS 与访问地址的更新顺序。
- 定时器根据当前启用的绑定和其证书账户选取 Certbot 目录，并以 `renew --cert-name` 续期相应证书。Certbot 使用它保存的签发配置。某张证书续期失败时记录原因，其他证书继续处理。已换下的证书文件保留，定时器只续期当前使用的证书。 [Certbot 管理与续期说明](https://eff-certbot.readthedocs.io/en/stable/using.html#renewing-certificates)

## 后台入口与安装

- 「域名与证书」增加「ACME 账户管理」入口，复用现有表单和列表组件。绑定域名、新建静态站及手动申请共用账户选择组件。概览快捷操作打开相同的手动申请入口。账户选项显示账户名和提供商。仅在申请证书时显示选择。
- 安装脚本在交互申请证书时先选择提供商，再显示所选条款。Let’s Encrypt 保留原默认邮箱和条款交互。全参数无人值守安装省略提供商时仍使用 Let’s Encrypt，并保持原调用方式。增加显式提供商参数；选择 ZeroSSL 时可在终端输入凭据，也可从指定凭据文件读取，密钥不放进命令行。
- 安装 CLI 与面板共用账户注册与签发流程。选择安装时申请证书，就先用填写的提供商、邮箱和条款创建首个账户，再尝试签发。签发失败保留账户和 HTTP 入口，若需重新注册可从面板补填凭据并重试。HTTP 安装跳过账户创建。在线脚本可能下载尚无多账户功能的旧发行包，默认 Let’s Encrypt 保留旧 CLI 调用。对要求 ZeroSSL 的安装，检测发行包能力并给出可理解的提示。
- 账户及新证书写入现有安装根目录的持久数据。旧配置和证书原地保留，升级时验证其续期。回退到功能发布前的版本时，新增账户的数据保留，新路径的证书需用支持多账户的版本管理。
