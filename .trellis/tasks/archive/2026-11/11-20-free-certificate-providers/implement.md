# 多提供商 ACME 账户实施计划

## 开发顺序

1. 为内置提供商和账户建立后端配置、SQLite 存储及后台管理接口。实现证书存留检查、账户删除和默认账户规则，验证无账户升级及已配置账户的兼容迁移。核对 ZeroSSL 绑定凭据的传递与错误输出。
2. 将账户选择传入共用证书申请流程，区分这次申请选择与当前证书实际账户。更新 Nginx 证书路径、签发成功记录、回退和自动续期。重点检查同一域名换账户后的成功及失败场景。
3. 接通面板、项目、网站绑定和新建网站的请求。实现「ACME 账户管理」和共用账户选择，体现默认标记、删除后的默认变更和无账户提示。覆盖「域名与证书」及概览上的手动操作。
4. 接通安装脚本及 `bind-panel` CLI。将安装时填写的提供商和邮箱持久化为首个 ACME 账户。验证交互默认、显式选择、HTTP 安装、旧发行包兼容和无人值守选项。同步安装帮助、用户文档与项目部署规范。

本任务按共享账户模型、签发、面板和安装的顺序实施，各入口通过同一套签发及续期验收。

## 验证

- Go 侧在受影响的包执行 `go test ./cmd/lpanel ./internal/panel -run 'Test.*(ACME|Certificate|Binding|Site)'`，并按改动补足新增入口的定向用例。验证有在用证书的账户及仅保留证书文件的账户都拒绝删除，默认账户维持原样。用无证书账户验证默认替换、删空、重启和重新添加。用替身核对不同账户路径、旧证书续期、同一域名切换成功与失败保留，以及密钥不会进入响应或操作输出。
- 前端执行 `npm --prefix web run typecheck`、`npm --prefix web run lint` 和生产构建。浏览器覆盖新增账户、证书存在时的删除提示、所有申请入口共用的账户选择及实际签发账户展示。
- 执行 `bash -n deploy/install.sh`、`bash -n tests/install-smoke.sh` 和安装冒烟。用替身验证 Let’s Encrypt 直接回车、选择 ZeroSSL、证书参数齐全时关闭输入仍可安装，以及无证书的安装。
- 有目标环境时，使用已解析的测试域名验证两家提供商的实际签发、HTTPS 生效及续期，记录实测和替身结果。Go、npm 和系统测试工作文件使用仓库 `.tmp`。
