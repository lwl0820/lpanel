# 宿主机防火墙

**范围**：`/api/v1/server/firewall` 仅供已登录管理员管理本机 UFW。面板安装、启动及升级不启用防火墙，不修改其他服务的规则。

**接口**：`GET /api/v1/server/firewall` 返回 `available`、`enabled`、`panel_port`、`rules` 和可选 `message`。`POST …/enable`、`POST …/disable` 启停；`POST …/rules` 接收 `{"port":2222,"protocol":"tcp","action":"allow"}`；`DELETE …/rules?id=…` 删除已列出的可操作规则。

**读写契约**：端口为 1 至 65535 的整数，协议为 `tcp` 或 `udp`，动作为 `allow` 或 `deny`。写操作成功后页面重新查询，不使用按钮状态代替系统状态。服务不可用、读取失败与未启用分别显示。

**启用条件**：当前配置的对外 `PanelPort` 必须与面板 Nginx 实际接收请求的端口一致。启用接口有独立代理位置，覆盖连接来源、目的地址、端口及代理版本。安装了 realip 模块的 Nginx 使用 `$realip_remote_addr` 取得直接对端；未编入模块时使用 `$remote_addr`。无法识别代理或连接时不启用。不要用浏览器自报的地址或 Go 收到的回环地址匹配来源限制。

**典型结果**：适用的放行规则不重复添加；缺少规则时先补放行再启用；若优先拒绝或无法证明现有规则允许当前来源，则不启用。复杂规则不直接编辑；SSH 不参与任何启用判断。

**验收**：非默认端口、来源限制、优先拒绝、添加规则失败属于定向回归。另在隔离网络模拟客户端：每次都建立新的 TCP 连接来核实面板仍能登录、SSH 访问随手工端口规则改变。不要在开发机启停 UFW。

**易错点**：已建立连接可能在启用后保持畅通，不能用它证明新连接可用。同样，停用时 `ufw status` 的 `inactive` 不表示下次启用没有规则。
